# Apex V3 — Architecture Research

Independent decision research for an e-commerce working environment in **Claude Code Projects**. This repository is **not the V3 backend**, a replacement coordinator, or a set of instructions to load wholesale into production.

## Purpose and scope

The owner wants creative, useful, self-directed assistance across store development, advertising, email, customer operations, SEO, research, images, video, and daily work, with little manual backend maintenance. The phrases "allt för min ehandel" and "inte restriktivt" mean a broad e-commerce scope and enabling collaboration; they do not authorize uncontrolled customer-facing actions.

Three streams inform a future fourth, fresh builder chat: this research, a V2 implementation audit, and a Red Team analysis. The builder must compare evidence at fixed commits, not count agreeing opinions. This stream has not approved V2's recent merges, audited every installed business skill, or produced the final CLAUDE.md.

## Evidence and implementation rules

Documents distinguish DOCUMENTED PLATFORM BEHAVIOR, VERIFIED TECHNICAL EVIDENCE, THIRD-PARTY EXPERIENCE, INFERENCE / HYPOTHESIS, RECOMMENDATION, and UNKNOWN / REQUIRES LIVE TEST. Supplied methods are not assumed to be platform specifications. A logical role does not require a new file; a current fact, behavioral instruction, and external-action approval have different owners.

Native-first, minimal hybrid, and external options are evaluated against useful outcomes and operator effort. No recommendation depends on repository stars, word count, a universal context quota, or a completion keyword. The builder may reject a recommendation when stronger V2, Red Team, or live evidence contradicts it; record the affected AR ID and reason.
